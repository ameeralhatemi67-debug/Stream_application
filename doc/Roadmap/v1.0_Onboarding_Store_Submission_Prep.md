# v1.0 — Full Onboarding Tour + Store Submission Prep

**Why this version exists:** the guided first-run tour ("making a full onboarding for the user... showing him around the application"), built now specifically because chat (v0.6) and phone streaming (v0.7) exist and are stable enough to actually show off — building this earlier would mean rebuilding it once those features landed. Also the point where everything left in the audit that isn't a feature gets closed out: Saudi legal/store policy, Android release mechanics, and whatever performance/UX polish didn't already ride along with an earlier version.

**Depends on:** v0.6, v0.7, v0.8 (the tour walks through map, discovery, live chat, and going live).

> **🛠️ Recommended Skills for v1.0:**
> - `google-playstore-toolkit` (`crgeee/google-playstore-toolkit` — Google Play Data Safety, Target SDK, 16KB page-size alignment)
> - `appstore-review-skill` (`devsemih/appstore-review-skill` — App Store pre-submission checks)
> - `claude-flutter-skill` (`Arcturus91/claude-flutter-skill` — interactive onboarding tour & overlay spotlights)
> *(If any skill is not installed, prompt the user or load it before execution).*

## Checkpoint 1 — Full Product Onboarding Tour

**🚀 Checkpoint kickoff:** push to GitHub.

### Phase 1: Tour Content & Flow
- Interactive walkthrough triggered on first sign-in or first guest entry, covering: the spatial GIS map, the discovery feed, live chat/reactions during a broadcast, and (for anyone who applies as a broadcaster) the go-live entry point.

- **Commit:** `feat(onboarding): skip/persist/replay behavior`

## Checkpoint 3 — Android Release Finalization

**🚀 Checkpoint kickoff:** push to GitHub.

### Phase 1: Real Signing + Application ID
- Generate the real upload keystore (you run this yourself, per `doc/Audit/07_Platform_Build_Readiness.md` §1a) and finalize `key.properties`.
- Finalize the permanent `applicationId` (still the Flutter placeholder as of the audit) — this is the last safe moment to change it.

### Phase 2: Play Console Listing & Closed Testing
- Store listing assets (icon, feature graphic, screenshots for phone + tablet), Play Console developer account, and the mandatory 20-tester/14-day closed testing track.

### Phase 3: Pre-Launch Report Review
- Upload a build and review Google's automated pre-launch report specifically for the 16KB page-size warning (Phase 7 §1c of the audit — depends on `flutter_vlc_player`/`webview_flutter_android`'s own native builds, not something fixable by editing this project directly) and any residual security flags.
- **Commit:** `docs(release): pre-launch report findings and remediation`
