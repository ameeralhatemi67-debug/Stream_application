# v0.5 — Backend Foundation (Supabase Migration)

**Why this version exists:** the audit found no backend at all — every "security" and "RBAC" boundary in the app today is a client-side check anyone can bypass by reading the compiled app. This version fixes that at the root, and because it does, it also closes VULN-AUTH-01, VULN-AUTH-02, VULN-AUTH-03, VULN-AUTH-04, VULN-RBAC-01, VULN-RBAC-02, and VULN-RBAC-03 from `doc/Audit/01_Security_Data_Protection_Audit.md` — not as separate bundled fixes, but because a real backend is what those findings were actually asking for. Also folds in the Phase 5 performance finding about `AppProvider`'s state-management pattern, since this version already reopens that file extensively.

## Checkpoint 1 — Supabase Project & Schema

**🚀 Checkpoint kickoff:** push current `master` to GitHub before starting.

### Phase 1: Housekeeping + Project Provisioning
- Add `.gitattributes` (`* text=auto`) to stop CRLF/LF noise in future diffs.
- Create the Supabase project (Free Tier), note the project URL + anon key.
- Add `supabase_flutter` to `pubspec.yaml`; wire project URL/anon key via `--dart-define` (not hardcoded — same fix pattern as the YouTube API key).
- Install the Supabase CLI locally for migrations (`supabase init`, `supabase link`).
- **Commit:** `chore(backend): provision Supabase project and add supabase_flutter`

### Phase 2: Schema Design
- Design and write the first SQL migration covering: `profiles` (mirrors auth.users, adds display name/avatar/role), `broadcaster_applications`, `organizations`, `org_venues`, `org_speakers`, `affiliation_requests`, `terms_and_conditions`, `audit_logs` — modeled directly on the existing Dart models in `lib/features/admin/models/` and `lib/features/organization/models/` so the migration is a straight port, not a redesign.
- Add `user_roles` and `user_permissions` tables now (empty/unused until v0.8, but the schema should exist from day one so v0.8 doesn't need another migration round on the same tables v0.5 already touches).
- **Commit:** `feat(backend): initial Supabase schema migration`

### Phase 3: Row-Level Security
- RLS on `broadcaster_applications`: applicant can read/write their own row while pending; only `admin`/`master_admin` roles can update status.
- RLS on `organizations`/`org_venues`/`org_speakers`: org members can read; only the org owner/co-owner (or admin tiers) can write.
- RLS on `terms_and_conditions`: public read, admin-tier write only.
- RLS on `audit_logs`: admin-tier read only, system-inserted (no direct user writes).
- **Commit:** `feat(backend): row-level security policies for core tables`

## Checkpoint 2 — Auth Migration (Google Sign-In → Supabase Auth)

**🚀 Checkpoint kickoff:** push to GitHub.

### Phase 1: Configure Supabase Auth
- Enable Google as an OAuth provider in the Supabase Auth dashboard, reusing the existing `serverClientId` from `google_auth_service.dart:48`.
- Confirm redirect URLs for Android/web (iOS deferred to v1.1).
- **Commit:** `feat(auth): configure Supabase Auth Google provider`

### Phase 2: Replace `GoogleAuthService`
- Replace the manual `google_sign_in` + `GoogleAuthService` flow with `supabase.auth.signInWithOAuth(OAuthProvider.google)`.
- **Delete the catch-block fallback entirely** (`google_auth_service.dart:96-107`) — a failed/cancelled sign-in must show a real error, never fabricate a session. This single change closes VULN-AUTH-01.
- **Commit:** `refactor(auth): migrate GoogleAuthService to Supabase Auth, remove insecure sign-in fallback`

### Phase 3: Migrate `AppProvider`'s Auth State
- Replace `_googleUserEmail`/`_isLoggedInStreamer` local flags with reads from the live Supabase session + `profiles`/`user_roles` tables.
- **Remove the hardcoded `_superAdminEmails` set** (`app_provider.dart:41-44`) — admin status now comes from the `user_roles` table, not a compiled-in string list. Closes VULN-RBAC-03.
- **Remove the `setRoleMode()` auto-assign-super-admin-email behavior** (`app_provider.dart:986-994`) — role changes now go through the real backend, not a local toggle. Closes VULN-AUTH-02.
- **Commit:** `refactor(state): AppProvider reads auth/role state from Supabase instead of local flags`

### Phase 4: Route Guards
- Add a `redirect:` callback to `GoRouter` (`app_router.dart`) checking the live Supabase session + role before allowing `/admin`, `/settings`, `/streamer-apply`, `/application-pending`. Closes VULN-RBAC-01.
- **Commit:** `fix(routing): add auth/role guards to privileged routes`
