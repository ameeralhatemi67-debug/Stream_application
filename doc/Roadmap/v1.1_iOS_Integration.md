# v1.1 — iOS Integration (Final Version)

**Why this is last:** your explicit preference. Everything else in this roadmap ships Android/web-first; iOS gets built once, at the end, when the feature set is stable — including its own version of phone streaming, rather than building that twice across the roadmap.

**Depends on:** everything (v0.5–v1.0) — this version brings the finished app to a second platform, it doesn't develop new product features in parallel with it.

## Checkpoint 1 — iOS Platform Bring-Up

**🚀 Checkpoint kickoff:** push to GitHub.

### Phase 1: Generate the Platform
- Run `flutter create --platforms=ios --org <your.reverse.dns>` on your own machine (per `doc/Audit/07_Platform_Build_Readiness.md` §2 Step 1) — this can't be run from within a cloud session, needs your local Flutter SDK.
- **Commit:** `chore(ios): generate iOS platform project`

### Phase 2: Info.plist, Privacy Manifest, ATS
- Add the usage-description strings (photo library, and camera/microphone once Checkpoint 2's phone-streaming work needs them), `PrivacyInfo.xcprivacy`, and confirm zero ATS exceptions are needed (should already be true if v0.5–v1.0's HTTPS-everywhere work is solid).
- **Commit:** `chore(ios): Info.plist, Privacy Manifest, and ATS configuration`

---

## Checkpoint 2 — iOS Feature Parity

**🚀 Checkpoint kickoff:** push to GitHub.

### Phase 1: Sign in with Apple
- Required per Apple Guideline 4.8 since Google Sign-In is offered. Add the `sign_in_with_apple` package alongside the Supabase Auth Google flow from v0.5, wiring it as a second Supabase Auth provider rather than a separate parallel auth system.
- **Commit:** `feat(ios): Sign in with Apple`

### Phase 2: iOS Phone Streaming
- Bring v0.7's phone-streaming feature (video + audio-only, RTMP to YouTube) to iOS, using an iOS-native RTMP encoder (e.g. an HaishinKit-based approach) behind the same abstraction the Android implementation already established, so the rest of the app's go-live UI doesn't need to know which platform it's on.
- **Commit:** `feat(ios): phone streaming (video + audio-only)`

### Phase 3: Background Audio & Playback Parity
- `UIBackgroundModes: audio` and confirm the floating mini-player / audio-only playback survives backgrounding on iOS the same way v0.7 confirmed for Android.
- **Commit:** `feat(ios): background audio playback parity`

## Checkpoint 3 — Apple Submission

**🚀 Checkpoint kickoff:** push to GitHub.
**🧹 Optional polish session:** a real-device pass on actual iPhone hardware (not just simulator) before archiving — several of this app's features (camera streaming, background audio, WebView playback) behave differently on real hardware.

### Phase 1: Developer Account & Provisioning
- Apple Developer Program enrollment, App ID + provisioning profiles matching the bundle identifier from Checkpoint 1, and confirming Mac/Xcode access is actually available (flagged back in the audit as a logistics item worth deciding early — this is the checkpoint where it can no longer be deferred).
- **Commit:** `chore(ios): Apple Developer provisioning`

### Phase 2: TestFlight Beta
- Internal, then external TestFlight testing per your own roadmap doc's timeline expectations.
- **Commit:** `chore(ios): TestFlight beta configuration`

### Phase 3: App Store Connect & Submission
- Finalize App Store Connect metadata using the privacy-label and store-copy drafts already prepared in v1.0 Checkpoint 2, upload the signed archive, and submit for review.
- **Commit:** `chore(ios): App Store Connect submission`
