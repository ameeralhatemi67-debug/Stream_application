## Exact retest script (two phones + Chrome)

Never capture a stream key, token, OAuth code or unredacted email.

1. **R02 conflict.** Phone 1: sign in as C, wait on Feed. Phone 2: sign in as C. *Expected:* phone 2 shows "Multiple Device Login Detected" after the splash, on whatever page it lands (repeat once with phone 1 locked for 2+ minutes first — the dialog must still appear; before this fix a silent phone 1 was taken over without a prompt). Choose **Continue as Viewer**: phone 2 on Feed, no studio icon. Kill and reopen phone 2: no dialog, still viewer. Record times.
2. **Transfer.** On phone 2: Settings → Broadcaster Mode on → dialog → **Transfer Broadcaster to This Device**. *Expected on phone 1 within ~1 s while foregrounded:* "Broadcasting stopped…" notice, lands on Feed, broadcaster mode off. If phone 1 was backgrounded, it must show the notice within a second of returning. Repeat immediately after cold-launching phone 1 (early-launch case) and record seconds. Transfer back to phone 1 the same way (Settings → Broadcaster Mode → Transfer). Then turn Wi-Fi off on phone 2 (now displaced) for 2 minutes and back on: phone 2 must stay viewer and must not reclaim; phone 1 stays primary.
3. **Studio (R06/R08/S01).** On the primary phone, own profile → studio icon. OBS tab: tap Go Live with no watch link → red message in the sheet. Phone tab: tap Open Camera with no key → message; with key but no watch link → message; on the non-primary phone → "not your broadcaster device" with the action button. Local tab → "not available", nothing saved. With a valid watch link for the authorized test broadcast and its key: Open Camera opens the camera screen; LIVE appears only after encoder connection and server acceptance.
4. **Displaced publisher.** While phone 1 publishes to the disposable test stream, transfer to phone 2. *Expected:* phone 1 leaves the camera screen, camera light off, YouTube Studio shows the encoder disconnect; Chrome feed/map drop phone 1's LIVE. Record the seconds.
5. **R06/R07 chat** (needs step 3 live): follow sheet R06/R07 unchanged.
6. **R08 admin live controls** (needs step 3 live): M ends, then removes a fresh ID; the phone must leave LIVE and release the camera (it does so through the same loss path). Check audit.
7. **R09.** M: Registry → map switch on D → reason required → hidden on B's map after refresh → audit shows actor, "Broadcaster hidden from map" and the reason. Switch back with a reason. Registry → **Revoke broadcaster approval** on D with a reason → D's phone downgrades without restart; D's organizations remain; audit shows the revoke. User Directory → ban D → D's phone shows the banned screen within a few seconds without restart; unban → access returns within ~20 s. Account deletion is a separate User Directory action; only on an account created for deletion.
8. **R05.** In a controlled window, pause sign-ups, sign in with N → must be refused; reopen; N succeeds.
9. **Wizard/avatar.** On the revoked D: Settings → Apply to Stream → wizard (not "pending"); close (X) from step 3 → confirm → back to Settings. Profile of an account without a photo shows an initial.
10. **Chrome reload hang capture.** Keep a signed-in tab 30+ minutes. If a reload hangs: DevTools Console (filter errors) and Network (filter `supabase`, `token`, `rest/v1`) screenshots with tokens/emails redacted, plus the address-bar route and whether the Flutter splash appeared.
