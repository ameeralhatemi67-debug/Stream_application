# Physical acceptance for the audited P6S build

Status: **NOT RUN. Owner physical acceptance is pending.** This script supersedes changed expectations in the 2026-09-25 script. All rows need a result, evidence and the exact build/device versions. The source baseline is `6c0e7c9`; later evidence-only commits do not change the app.

## Setup

Use two physical Android phones, a laptop running Chrome and OBS, and four non-production roles: broadcaster C, a different approved broadcaster C2, ordinary viewer V, and admin M. Both phones must be able to sign in as C for the transfer case. Record Android versions, manufacturers, Android System WebView version, Chrome/OBS versions, app commit/build hash and network type. Use separate viewer identities, not just two screens of the broadcaster account.

Use a disposable/local backend reachable by the phones, or a separately authorized staging backend. **Do not use `project/dart_define.local.json`; it points at production.** This audit did not authorize or perform a hosted migration. The no-credentials debug APK compiled during this audit is a build check, not a configured acceptance build.

Before any separately authorized staging rollout, stop existing broadcasts, verify there are no live legacy profile/org flags, and exclude old app builds. Apply the original session migration `20260925100000_broadcast_sessions_and_live_controls.sql`, then `20260926010000_fence_concurrent_broadcast_end.sql`, then `20260926020000_broadcast_identity_and_expiry_fences.sql`. A fresh database applies the whole migration history. Do not attempt a hot migration of ambiguous legacy broadcasts.

Configure C's approved channel and a working, appropriately restricted YouTube API key in the non-production build. Create a test broadcast on that channel manually. Keep its ingest key private. Record only watch IDs, session IDs, timestamps, error codes and screenshots that do not expose keys/tokens.

For each actual media run, display a unique visual nonce and speak it aloud, for example `P6S-20260926-1430-C-1`, then change it after 15 seconds. The independent viewer must see and hear both values. A LIVE badge, server row, moving preview, YouTube thumbnail, chat message or RTMP connection alone does not pass audiovisual acceptance.
