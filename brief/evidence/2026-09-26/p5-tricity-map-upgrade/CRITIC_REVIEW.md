# Independent critic reviews

Rules (from `brief/research/p5-tricity-map-upgrade/OPUS_EXECUTION_PROMPT.md`): at most **three** critic reviews for the whole map upgrade. Four categories scored 0-10 by the critic, not the implementer: Functionality; Accessibility and platform compatibility; Integration and connectivity; Ease of use. Below 8 fails a category. Critical/high defects, unlicensed assets, failed G0 gates or missing essential acceptance evidence block acceptance regardless of scores. Missing physical evidence is provisional, not "verified good". Each round is tied to the reviewed commit; any later source fix invalidates affected evidence until re-checked.

Rounds used: 1 of 3 (round 1: NEEDS WORK, see below).

### Confirmed good (independently checked)

- **Local range client** (`local_pmtiles.dart:32-62`): only GET to the one internal URI, single `bytes=a-b`, 416 past EOF, 4 MiB cap, 206 + Content-Range, closed on dispose; the provider disables the disk cache and keys caches by pack SHA. No server, fork or parser.
- **Pack verification** (`map_pack_controller.dart:171-245`): schema 1, native zoom 0-15, per-file size + SHA-256 for pack and both styles, local-only style rule, header zoom re-check; any failure is `unavailable` with a coded problem, never a partial map. `ensureOpened` is only called from `initState` (no rebuild retry loop).
- **Pack data**: `pack-validation.json` really shows 8,298/8,298 slots, 0 missing, 0 decode errors, per-zoom counts and named control tiles with road/building/POI counts; manifest hashes match; the extract was a ~12 MB regional read (no planet download).
- **Viewport policy math** (`map_viewport_policy.dart`): containment clamps the centre by half a viewport in Mercator space; `minZoom = max(contain, overviewFit)`; feasible-canvas shrink; per-frame clamping in `_moveTo` (`spatial_map_screen.dart:121-149`). Every programmatic path I traced ends in `_moveTo`: overview (`:166`), dropdown and city search (`:172`), venue focus/list/search (`:186-207`, `:543-552`), cluster tap (`:355-365`), marker double-tap (`:446`, `:1066`), resize/tab restore (`:154`, `:531-537`). Gestures, wheel, keyboard and the built-in double-tap use `CameraConstraint.contain(navigation)` plus `minZoom/maxZoom` (`:584-595`), rotation off. The picker uses the same policy (`location_picker_modal.dart:108-126, 203-229`).
- **Domain filter and data truth**: `isInTricityMapDomain` rejects non-finite, (0,0) and out-of-rectangle points; applied to both current and cached pins (`map_visible_catalog.dart`). Records are not mutated. Moderation (verified/hidden), null-vs-empty snapshot, cached-marker ID reconciliation and the `isOnline`-gated live layer are unchanged in the diff. Directions keep exact coordinates and now show a localized failure.
- **Service worker safety** (`web/streamer_offline_sw.js`): it never writes to the cache, ignores non-GET and every origin except same-origin and the two gstatic CDNs, is network-first, and is bypassed by preparation's `cache:'reload'`. It cannot store Supabase/API/auth responses. The offline log shows 27/27 responses from the service worker and only the backend (port 9) failing.
- **Picker truthfulness**: `suggestedAddress`/`city` guessing is gone; only the tapped point returns; typed venue text and chosen city are kept; legacy out-of-area points are shown and kept; cancel returns null and keeps the old point; branch coordinates are nullable instead of a hard-coded Al Khobar point.
- **Licensing**: OSM/ODbL + Protomaps produced-work notice, Natural Earth, app-authored styles, BSD renderer notices, BSD PMTiles reader copy with its LICENSE; no sprites/glyphs; no Esri/OSM tile URLs remain. I found no unlicensed asset. The credit rail is visible in every screenshot state (online/offline/pack unavailable/Arabic/Windows).
- **Arabic**: joined Arabic place and street labels in Chrome (A03-03, A03-04 deep zoom, never browsed) and Windows (W04); the G0 tofu regression is documented and fixed for a fresh session.

### Scores

**1. Functionality: 7 / 10 (fails; provisional).**
Evidence: code review of the pack controller, range client, policy, domain and picker; my analyze and 727-test run; the pack-validation JSON; Chrome offline logs and screenshots; Windows render JSON and screenshots. Confidence: high for pack verification, zoom limits, camera containment and domain filtering (unit tests plus the real engine on Windows/Chrome). Low for native first-launch offline, reboot and version replacement (no Android runtime of any kind). Why below 8: D1 is a false-ready state in exactly the failure/recovery path the task calls out. D2 leaves an untruthful/unsafe coordinate path downstream of the new picker. Accurate outlines (A11) remain unmet (external, correctly disclosed). The core native first-use-offline claim is unverified on the target phone.

**2. Accessibility and platform compatibility: 6 / 10 (fails; provisional).**
Evidence: Arabic screenshots (Chrome, Windows); layout-sweep and semantics widget tests; credit/chip/cluster semantics in code; style `text-size` scaling with text scale (clamped 1.0-1.6). Confidence: medium on Chrome/Windows. None on Android (no device or emulator), TalkBack, keyboard traversal or device text scale. Why below 8: zero Android runtime evidence for the primary platform; D3 (picker not operable without a pointer); D5 (sub-48 px targets on the map's own controls); D6 (RTL framing uses LTR insets); web offline Arabic labels depend on D1. Documented platform limits (web first visit, eviction, platform fonts) are honest.

**3. Integration and connectivity: 7 / 10 (fails; provisional).**
Evidence: diff of catalog, moderation and cached-marker code (unchanged semantics plus the domain filter); backend-unreachable runs on Chrome/Windows; map independent of `isOnline`; route/stream guards untouched; one shared `MapPackController` for map and picker; no duplicate renderer; Esri/OSM/cancellable provider removed. Confidence: medium, because nothing ran against a reachable backend. Why below 8: A14 "pack ready x backend current", A15 reconnect-removal, and A17 map->stream->map with mini-player coexistence have no runtime evidence. D2 is a real integration defect between the new picker and the approval/profile/directions path. The ~12 MB pack stays in memory for the process lifetime once opened, and its effect beside playback has not been measured.

**4. Ease of use: 7 / 10 (fails).**
Evidence: screenshots (compact chip, matching city dropdown and search, details-sheet wording, honest unavailable card with Retry and venue list, member list at max zoom) and a review of the strings. The map-versus-connection distinction is clear, city selection is simple, and the credit is small and readable. Why below 8: D4 (web offline preparation is effectively hidden); D3 (the picker needs precise tapping and has no centre-pin option); D12 (duplicate Retry); D7 (misleading status in the picker). Search matches only exact substrings, so "Alkhobar" or "Khubar" find nothing.
