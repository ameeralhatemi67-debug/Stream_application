## P1d decisions (Claude Code Opus, 2026-09-21)

| # | Decision | Reasoning |
|---|---|---|
| D-28 | A migration that provably cannot apply anywhere may be edited in place. | The "new migrations only" rule protects databases that already ran a file. `20260920140000_policy_quality.sql` aborts at statement 35 on `42883`, so no database can hold it, and no later migration can repair it because the chain never reaches one. Two dead `chat_sender_info(uuid[])` statements were removed and the reason written into the file. Same reasoning the P1c ledger used for shipping `is_banned` at an earlier timestamp. |
| D-29 | The `streamer_public_profiles` repair goes in a migration timestamped *before* `20260830180000`, not by editing it. | `create or replace view` cannot reorder columns, and the failure aborts the chain, so a forward-only fix is impossible. An interleaved timestamp keeps the edit out of an existing file, and `db push` skipping it on an already-migrated production project is the safe outcome rather than a hazard. |
| D-30 | Table privileges are part of the access-control design, not incidental plumbing, and are asserted in both directions. | 110 policies sat on tables with no DML granted to `anon`/`authenticated`; privileges are checked before RLS, so every policy was dead and the app was uniformly `42501`. Grants are now derived per table from the commands that actually have a policy, and `rls_catalog.test.sql` R10/R11 fail if a policy loses its grant or a grant loses its policy. |
| D-31 | Withhold a privilege wherever a command is meant to be impossible, even though RLS already denies it. | `profiles` gets no DELETE (erasure is `delete_own_account()`), `affiliation_requests` no DELETE (cancelled by status), `audit_logs` no INSERT (RPC only), `device_sessions` no writes (RPC only), `stream_viewers` nothing at all. Two layers, so adding a policy by accident is not sufficient to open a path. |
| D-32 | `log_audit_event()` gets the smallest possible organization guard now; the real model waits for P7. | It accepted any `p_organization_id` from any signed-in caller, so the one table meant to be trustworthy could be poisoned with entries against unrelated organizations. The guard allows a null organization, `is_org_member()`, or admin-tier. Per-capability organization authorization is P7 and is recorded NOT DONE. |
| D-33 | Exact public coordinates (VULN-COMP-02) are reported, not silently decided. | Restoring `latitude`/`longitude` to the anon view was forced by D-29, and it reopens a vulnerability `20260822140000` had closed. Every remedy (rounding, fuzzing, radius) changes what the map shows to users, which is the owner's call, and `20260822140000` itself deferred it. Recorded as owner action 2 with the exact SQL for the rounding option instead of being chosen here. |
| D-34 | A pgTAP assertion that cannot reach the thing it claims to test is rewritten, not deleted. | `streamer_assets.test.sql` proved its delete policy with a direct `delete from storage.objects`, which the storage schema's `protect_objects_delete` trigger refuses before RLS is consulted (and it cannot be disabled: `postgres` is not a member of `supabase_storage_admin`). Those two cases now assert `can_write_streamer_asset()`, the predicate the delete policy is built from, with the reason written into the file. |
| D-35 | Where a privilege revoke turns an empty read into an error, the test asserts the error. | `stream_viewers` and `follows`/`bookmarks` reads by the wrong role now raise `42501` instead of returning zero rows, because the privilege is gone. Denial before RLS is the stronger outcome, so `viewer_presence` (06 A12) and `follows_and_bookmarks` use `throws_ok` rather than being relaxed to match. |
