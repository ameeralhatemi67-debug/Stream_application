# 03 — Work plan (ordered by risk and dependency)

Conventions: one commit per phase (more if a phase is large) with conventional messages; **never push**; **never touch a linked/production Supabase** (local stack only, see 05 D-14). Every phase ends with the **checkpoint routine** (04 §C): `flutter analyze` = 0, `flutter test` green, `node brief/tools/gates.mjs`, ledger entry, budget check. Percentages are *first guesses of one 5-hour window*; after each phase write the real burn (Δ of `used_5h`) in the ledger and re-plan — your own numbers beat mine.

Order: **P0 → P1 → P2 → P3 → P4 → P8A → P6 → P5 → P7 → P8B → P9.** P1.2 (live-state RPC) is a prerequisite for P3, P6, P7. P2 shrinks the surface before the P4 UI pass touches files.

Cut list when budget is short (drop from the bottom, never P0-P3, never P9): 1) P7 beyond server-side enforcement + minimal org profile; 2) P5 offline tile pack (keep detection, cache, visuals); 3) P6 admin extras beyond user directory + kill switch; 4) P4 i18n-literal migration outside Settings/Admin/Live/Onboarding. Anything cut goes in the ledger as NOT DONE with the reason.
