# CODE_MAP (paths relative to `project/`; line numbers from the worktree)

Key fact: the existing "Hedayah skin" is NOT a set of separate screens. It is a theme swap (`AppSkinTheme` ThemeExtension) plus ~44 inline `context.isHedayahSkin ? X : Y` branches. Only 3 screens have a real second widget tree: Welcome (`HedayahWelcomeView`), Splash (`_HedayahSplash`), ViewerSetup (`_buildHedayah`). Wide layout (>=1024) is a separate axis (`usesHidayahWeb`), not tied to skin.

## E. What makes a third skin awkward
1. Enum/parse: `AppSkin{gold('gold-black'), hedayah('hedayah-skin')}` (`core/theme/app_skin.dart:10`); `AppSkin.tryParse` switch (:24) lists strings explicitly; default fallback `AppSkin.gold` in `readAppSkin` (`core/services/app_skin_preference.dart:12`, prefs key `app_skin`, web `?skin=` link, stored id) and in `AppProvider._appSkin` (:842), `StreamerApp.initialSkin` (main.dart:30), `ActiveSkin.current`, `AppSkinContext.skin`.
2. Binary theme build: `AppTheme.forLocale(locale, {skin})` (`app_theme.dart:112`) is `skin == AppSkin.hedayah ? HedayahSkin.theme : _buildTheme` (else = gold); cache key uses `skin.id`. Each theme must include `extensions: [AppSkinTheme(skin)]` (gold :127, hedayah hedayah_skin.dart:143), else `context.skin` silently becomes gold.
3. `ActiveSkin.hedayah` boolean used without context: `HidayahText.display` (hidayah_web_kit.dart:33) and lessons text styles; `ActiveSkin.current` is a mutable global set in `forLocale`.
4. `SkinFonts.ensureLoaded(skin)` returns immediately unless `skin == AppSkin.hedayah` (`skin_fonts.dart:23`); called from `main.dart` and `AppProvider.setAppSkin`.
5. `context.isHedayahSkin` binary (else = gold) in: app_router.dart:652,871; ca_button.dart:128; ca_cards.dart:28; ca_fields.dart:23,304,481-486; ca_icon.dart:80 (asset dir `assets/hedayah|canopy/icons`); ca_navigation.dart:72; language_switcher.dart:62; skin_colors.dart:11 (`pageGround`); welcome_screen.dart:160; viewer_setup_screen.dart:229; role_select_screen.dart:73,109,162; app_splash_screen.dart:114; discovery_feed_screen.dart:287; discovery_web_view.dart:524,549; lessons_icons.dart:109; lessons_kit.dart:242,427,483,771,773; lessons_shell.dart:117,123,133; settings_screen.dart:391-401,459; application_settings_section.dart:84; hidayah_web_header.dart:66,307; hidayah_web_kit.dart:185,240.
6. Explicit `skin == AppSkin.hedayah` / `AppSkin.values`: `appearance_settings_section.dart:20,41-42 (values loop; "first" gets no left gap),54-55 (nameOf: ternary -> `skin.hedayah`/`skin.gold` i18n keys; a third value would show "gold"),117,136 (tile preview)`.
7. The picker (`_choose` -> `provider.setAppSkin`) only needs the enum value plus i18n `skin.<name>`; `setAppSkin` itself is generic.
8. Hedayah icon coverage test and the `hedayah` SVG set must be copied for a new set; `CaIcon` has only two asset directories (ternary).
9. Shell is not skin-aware except colours: `CaNavBar` asserts 3 tabs; `ResponsiveScaffoldWithNestedNavigation` hardcodes branch to `HidayahWebSection` mapping `[discover,map,lessons]`.
10. Wide layout (>=1024) is independent of skin and hard-wired to the gold website kit (`usesHidayahWeb` branches in feed, live room, profile, map, studio, shell); a third skin must either reuse or override all of them.
11. Hedayah wide-layout and phone share the same Hedayah theme; there is no skin-specific screen registry, so a new skin's screens need a dispatch at the top of each screen's `build` (as Welcome does) or a router-level builder switch.
